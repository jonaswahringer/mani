# Core-reader agent test — macOS — 2026-08-17

Verdict: **PASS WITH CONCERNS**

An independent agent ran this test on the `minj` Mac mini in its own terminal
session. It made no repository edits.

## Passed

- `cargo build`, `cargo test --all-targets`, and strict Clippy completed.
- `--short` printed only the Custom Guide introduction.
- default `--print` preferred Custom, while `--official` printed the installed
  man page.
- without a Custom Guide, `--short git` used `git --help`, not the man page.
- missing Custom, invalid config, conflicting source flags, missing sources,
  and `--ignore-config` produced the expected outcomes.
- redirected `auto`, `always`, `never`, and `NO_COLOR` behavior matched the
  specification.
- a PTY session rendered the Outline Browser with the Custom source, guide
  path, outline, document, and key footer.
- the agent sent search, source-switch, and quit keys through a delayed PTY
  session. Mani exited cleanly and restored the terminal.

## Concerns found

The agent found that a trailing command option was consumed as Mani's version
flag:

```sh
MANI_HOME=/tmp/mani-slice1-e2e ./target/debug/mani --short git --version
```

This is now covered by an automated regression test. Mani treats every token
after the first Command Path token as part of the path and rejects `--version`.

The Interactive View still exits when neither source exists:

```sh
MANI_HOME=/tmp/mani-slice1-e2e ./target/debug/mani definitely-not-a-command
```

The specification calls for a recovery screen with the Command Path and exact
Custom Guide location. That viewer state remains an implementation gap.

## Environment limitation

One delayed automation PTY reported a zero-sized terminal, so its captured
redraw stream could not prove the visible search and source-state text. The
automated Rust PTY test uses an explicit 100-by-24 terminal and covers those
visible transitions.
